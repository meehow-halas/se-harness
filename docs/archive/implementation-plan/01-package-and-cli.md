# 01 — Package and CLI

## Goal

Make `se-harness` an npx-runnable package whose CLI binary is `seh`, whose only commands are `install` and `uninstall`, and whose install writes the project-local bootstrap the PRD requires.

## Scope in

- `package.json`: name `se-harness`, `bin.seh` → CLI entry, version used as `.seh/VERSION`, `files` so npm/GitHub installs include payload dirs and `src/`.
- `src/`: `seh install` and `seh uninstall` only.
- Payload dirs exist at package root: `agents/`, `skills/`, `brainstorm/`, `references/`, `scripts/` (`packs/` exists).
- A thin `skills/` stub for `/<prefix>setit-se` if install needs a source file.
- Idempotent install and uninstall in the current working directory (the consuming project).
- Install ensures project-root `.gitignore` contains `.seh/` and `harness.credentials.local.json` (creates it if missing). Uninstall does not edit `.gitignore`.

Invocation (both first-class): `npx -p se-harness seh install`, `npx -p github:meehow-halas/se-harness seh install` (also `#<ref>` and `https://github.com/...`). Uninstall uses the same source.

`seh install` copies `.seh/{agents,packs,skills,brainstorm,references,scripts}/` (same names, no remap), writes `.seh/VERSION`, writes the host `/<prefix>setit-se` skill from package `skills/`. It does **not** generate agents, work skills, rule packs or `harness.config.json`. Second install refreshes `.seh/` and the setup skill, no duplicates. If `harness.config.json` exists, install may print that the user should run `/<prefix>setit-se`.

`seh uninstall` removes `.seh/` and the install-owned setup skill. Keeps `harness.config.json` and files generated by setup. Idempotent.

## Scope out

- Any CLI beyond `install` / `uninstall`. Never `npm install -g`. Never write to `~/.claude/` or other machine-wide paths.
- Generating live agents, work skills, rule packs, `harness.config.json`.
- Filling agent/skill/script bodies (phases 2–7). Finishing setup (phase 5).
- Inventing a test suite.

## Decisions taken

- Binary name `seh`. Exact file names inside `src/` are the implementer's choice.
- Missing payload subdirs: copy what exists; a stub is enough where the setup skill source is required.

## Files likely touched

- `package.json`, `src/*`, `skills/setit-se/` (stub), `agents/`, `skills/`, `brainstorm/`, `references/`, `scripts/` (created if missing)

## Acceptance criteria

- `package.json` exposes binary `seh`.
- In a throwaway directory `seh install` creates `.seh/` with the six subdirs (empty OK), `.seh/VERSION` equal to package version, and the project-local `/<prefix>setit-se` skill.
- Second install does not duplicate trees.
- `seh uninstall` removes `.seh/` and that skill and leaves a pre-existing `harness.config.json` in place.
- No other subcommands accepted.

## Tests
