# Changelog

All notable changes to `se-harness` (`seh`). Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions: [Semantic Versioning](https://semver.org/).

## [1.5.0] - 2026-11-18

### Added

- `/<prefix>designit`: the Designer designs UX/UI only, before the spec, and writes `docs/designs/<slug>.design.md` in the repo. Reads and writes no tracker, creates no spec, prompt or log, uses no git. Needs `agents.designer.enabled`; otherwise `BLOCKED`. Offers `/<prefix>planit … <path>`.
- `references/design.design.md`: template of the design file (`id`, `title`, `status` `draft` | `ready`; UX/UI sections, `D<n>` decisions, `UX:` criteria).

### Changed

- Designer (`agents/designer.md`): second contract, `Design file: <path>` (writes only that file, `D<n>` inside it, `ready` after acceptance or write).
- Architect (`agents/architect.md`): input `Design: <path>`. Writes `ui: true`, the UX/UI decisions section and `UX:` criteria from the file; conflict is a `Q<n>`; `draft` asks (interactive), `BLOCKED` (critical) or `Q<n>` (autonomous); logs `design: <path>`; never edits the file.
- `/<prefix>planit`, `/<prefix>runit`: accept a design file the user names and pass `Design:`; the Designer stage is skipped when the spec has a UX section.
- `/<prefix>setit-se`, `src/cli.js`, `references/AGENTS.md`: `designit` in generation, prefix cleanup, host commands, `invokePrefix` and the consumer skill list.

## [1.4.1] - 2026-11-18

### Fixed

- `references/harness.config.md`: `agents.designer.enabled` on the first `/<prefix>setit-se` run is asked once (recommended `true` when a UI stack was detected), not written without a question. Matches `/<prefix>setit-se` and the PRD.
- Designer in `interactive`: approval of a **new** UX section can now arrive as `User approval:` from `/<prefix>planit` / `/<prefix>runit` (before, only a change to an existing section was forwarded, so a rerun could stop again on the same section).
- `references/spec.feature.md`: no placeholder `## UX/UI decisions` heading. A spec copied from the template with `ui: true` kept that heading, so `runit` skipped the Designer stage and the `doit` / `checkit` gate let the task through.
- `runit`, `grillit`, `references/session-fanout.md`: role lists name the Designer (same mode as the run; no persona interviews; allowed as a subagent in a fan-out child).

## [1.4.0] - 2026-11-18

### Added

- Designer agent (`agents/designer.md`): for a spec with `ui: true` and `agents.designer.enabled: true` it adds the **UX/UI decisions** section, `UX:` acceptance criteria and `D<n>` log rows. Same modes as the Architect; read-only on application code; no git; status unchanged. Run by `/<prefix>planit` and `/<prefix>runit` (stage 1b), not by the Architect.
- Spec frontmatter `ui` (`true` | `false`, absent = `false`), set by the Architect; spec and log templates updated.
- `harness.config.json` `agents.roles.designer.model` and `agents.designer.enabled`; `modelSuggest.designer` in `hosts.json` (equal to `implementer` on every host). `/<prefix>setit-se` asks the Designer model per host, migrates a config without the role, and asks whether to enable the Designer.
- Manual test scenario for the Designer (`docs/archive/designer-agent/manual-test.md`).
- Rule pack `ux-a11y` (`a11y.md`, `states.md`, `touch-i18n.md`): measurable WCAG 2.2 AA, state and touch-target rules scoped to UI files, generated by `/<prefix>setit-se` when a UI stack is detected. Consultant treats a violation as `must-fix`.
- `scripts/record-change <task> --text <one line>`: adds the change to `CHANGELOG.md` (Unreleased, Changed) when `agents.reportChange` is not `false`. With `false` it prints `UNCHANGED` and writes nothing; the flow does not stop.
- `harness.config.json` `agents.reportChange` (boolean, default `true` when missing).

### Changed

- `/<prefix>doit` and `/<prefix>checkit` stop a task with `ui: true`, the Designer enabled, and no UX section: `BLOCKED: <KEY> needs the Designer stage — run /<prefix>planit <KEY>`. `/<prefix>shipit` children start at the Designer stage when it is missing.
- Five product agents instead of four (`references/AGENTS.md`, `/<prefix>setit-se` role tables and generation, Codex TOML for the new role).
- `commit-task` adds a changed `CHANGELOG.md` by itself when `agents.reportChange` is `true` or missing. With `false`, an invalid value or no `node` it adds nothing extra and does not stop; listed paths, `CHANGELOG.md` included, are always committed.
- `record-change` places the Unreleased section above the first `## ` heading of any form (`## 1.2.0`, `## v1.2.0`), and reuses a plain `## Unreleased`.
- Reviewer, Architect and `checkit`/`shipit` texts say "change record"; the Reviewer calls `record-change` after acceptance and no longer lists `CHANGELOG.md`. Implementer and `doit` keep the explicit "do not edit `CHANGELOG.md`", now also over project rules that ask for a changelog line.

## [1.3.3] - 2026-11-18

### Fixed

- `/<prefix>setit-se` work skills: the frontmatter `name:` is the bare `<prefix><name>` (for example `_doit`), no leading `/`. The step said "(the slash command)", so a generated copy could read `name: /_doit`, and the host then invoked `//_doit`.

## [1.3.2] - 2026-11-17

### Changed

- `/<prefix>runit` with several keys and no spec: not `BLOCKED`; each child starts at Architect. With git disabled, several `runit` keys run in this session in dependency order from `fanout-plan` (`mode: sequential`), not in the order given; a sibling `depends` found by Architect sends the key back to `waiting`. No dependency ordering in a parallel `runit` fan-out (git enabled): a sibling `depends` already in the spec means the key is not started, and one found by Architect stops that child after the Architect stage; both are `BLOCKED` (rerun after the dependency is merged). Dependency-ordered automation stays `/<prefix>shipit` with specs written beforehand. Removed contradicting texts (`runit is one task` block, PRD stops list). `shipit` keeps its missing-spec `BLOCKED`.
- `/<prefix>doit` and `/<prefix>checkit` with several keys and git disabled: run in this session in dependency order from `fanout-plan` (`mode: sequential`), not in the order given. With git disabled this holds on every host, `manual` included (no per-key commands are printed).

### Fixed

- Architect no longer stops on an open `depends`: it writes the spec and records the dependency, so dependent tasks can be specced ahead for `/<prefix>shipit`. Implementer and Reviewer still gate on it.
- `/<prefix>runit`: dependency gate right after its Architect stage (before `start-task`): an open `depends` is `BLOCKED` and the spec stays in the launch checkout, so the rerun does not re-run Architect or reuse a worktree cut from the old base. Resolve reads the task worktree copy when a seh worktree exists.
- Fan-out and `/<prefix>shipit`: a child waiting on the user (open `Q<n>`, interactive acceptance) counts as running; its dependents keep waiting and the run report waits for it. Only a final `BLOCKED:` drops a key.
- Git disabled (`sequential`): a `Q<n>` is answered in the same session and the key continues; it is no longer dropped.
- `/<prefix>shipit` resolve checks `pr-state` first: a merged key is skipped without a spec check, so a rerun no longer reports it `run /<prefix>planit first` when its spec is only on the base branch.
- `/<prefix>runit` with no local spec (files / read-only tracker, git enabled) checks `pr-state` before Architect: an open PR is `task is already done`, a merged one `task is already merged`, so a rerun after `return-to-base` no longer specs the task again.
- `/<prefix>shipit` on the desktop host: a key at `in progress` / `implemented` / `in review` with no live session is planned again (its child resumes at the first missing stage) instead of staying `running` forever. A `runit` run that starts at the Reviewer stage gets `Worktree:` from `start-task` (idempotent). The run report drops the always-zero "question pending" count.
- Fan-out: `/<prefix>planit` with several keys no longer reports a key without a spec as `BLOCKED: run /<prefix>planit first`; its child writes the spec. Only `doit`, `checkit` and `shipit` keep that stop.
- `manual` hosts: printed per-key commands carry the user's mode words (for example `samodzielnie`). The fan-out end report asks nothing in `autonomous` mode.
- Reviewer auto-merge (`Auto-merge: yes`): after resolving a conflict with the base branch, the project's test/lint/typecheck runs before `push-task`; failing checks are `BLOCKED` with no merge. Up to 3 conflict-resolution attempts (was 1), since the base moves while sibling tasks merge.
- `references/harness.config.md`: ADO field-map values are explained in place instead of linking to a repo planning doc that is not installed in consuming projects.

## [1.3.1] - 2026-11-17

### Changed

- Skill names swapped. `/<prefix>shipit` is now the parallel, dependency-ordered, auto-merge skill for many specced tasks (was `/<prefix>runit`); `/<prefix>runit` is now the single-task pipeline Architect → Implementer → Reviewer (was `/<prefix>shipit`). Children started by `shipit` run `/<prefix>runit <KEY>`; the run report is `docs/run-reports/<YYYY-MM-DD-HHMM>-shipit.md`; `fanout-plan` accepts both names as before. Migration: replace old `/shipit` with `/runit`, and old `/runit` with `/shipit`. `/<prefix>setit-se` regenerates both skills on the version change.

### Fixed

- `.seh/scripts/ado` no longer stops with `BLOCKED: this directory is not a git repository` in a project without git (git disabled). It reads `harness.config.json` and `harness.credentials.local.json` from the project root, and from the main checkout only when run inside a git worktree, the same as `jira`.

## [1.3.0] - 2026-11-17

### Added

- `.seh/scripts/merge-pr <task>`: `gh pr merge <number> --squash` for the open PR of the task branch into `agents.baseBranch`. Conflict, missing PR, and gh failures are `BLOCKED:`; an already merged PR is `UNCHANGED`. No `--auto`, `--admin`, `--delete-branch`, rebase, or force.
- `.seh/scripts/pr-state <task>`: read-only `state: merged|open|none` (with `url:`, and `merged_at:` / `merge_commit:` when merged) for `<task>` or `<task>-N` into the configured base.
- Reviewer merge step (opt-in): with launch line `Auto-merge: yes`, after `open-pr` the Reviewer runs `merge-pr` (one `update-from-base` retry on conflict), then `return-to-base`. `/<prefix>shipit` forwards the line only together with `Fan-out child: yes`; a user-launched run never merges. Default behaviour is unchanged.
- `/<prefix>runit` work skill: many specced tasks (named keys, or all `todo` tasks in a files / read-only tracker) run as one `/<prefix>shipit` session each in parallel, with auto-merge into `agents.baseBranch`. A task with `depends` starts after its dependency is merged (`pr-state`). One go-ahead question; `manual` hosts print one command per ready key and recompute on rerun. Writes a run report to `docs/run-reports/<date>-runit.md` (not committed, never sent to Jira/ADO). `fanout-plan` accepts `--skill runit`; `references/session-fanout.md` allows `Auto-merge: yes` in the child prompt for `runit` only.

## [1.2.0] - 2026-11-14

### Added

- Session fan-out for multi-key runs. `/<prefix>planit`, `/<prefix>doit`, `/<prefix>checkit` and `/<prefix>shipit` given two or more keys plan with `.seh/scripts/fanout-plan` (`ready`, `waiting`, `blocked`, default `--max 4`). On the Claude Code desktop app each key starts as its own session (`references/session-fanout.md`). Other hosts (`sessionSpawn: manual`) print one command per key. Without git, the planner returns `sequential` and keys run one after another in the current session. Manually tested on each host.
- Optional git. An empty `agents.baseBranch` disables git for the harness: agents and skills skip branch, worktree, commit, push, PR, and return steps. `start-task` prints `worktree: <launch checkout>`, multi-key runs are sequential, and a task is done when accepted and written to files. `/<prefix>setit-se` asks for the base branch (suggested `dev`) and can leave it empty.
- Azure DevOps Boards tracker in full write (`agents.tracker.kind: "ado"`). `.seh/scripts/ado` provides `meta`, `get`, `create`, `set`, `comment`, `transition`, and `link` over WIT REST 7.1, with the PAT in `harness.credentials.local.json`. `/<prefix>setit-se` adds, changes, and removes the tracker. Spec, prompt, and log live on the work item; HTML fields are read as plain text. Status changes go to mapped state names. Read-only mode is listed under 1.1.0.
- Codex as the fourth host: a `codex` row in `references/hosts.json` plus format adapters (`references/codex-adapters.cjs`), no second template tree. New optional row fields: `agentFormat`, `hooksMatcher`, `invokePrefix`, `skillHide`, `rulesIndex`.
  - Skills install to `.agents/skills`. A skill is invoked as `$<prefix>setit-se` (or picked in `/skills`); Codex has no `commandsDir`, and nothing is written under `~/.codex/`. Skill text uses the row's `invokePrefix`.
  - Agents are TOML in `.codex/agents/<name>.toml` (`name`, `description`, `developer_instructions`; `model` only when set, otherwise the session model is inherited). A Codex subagent inherits the parent sandbox, so Consultant read-only is instruction text only.
  - Work skills get `<skill>/agents/openai.yaml` with `policy.allow_implicit_invocation: false`.
  - Rule packs go to `.codex/rules/*.md`, and `/<prefix>setit-se` keeps one seh-managed section in `AGENTS.md` that points at them. Path scoping is soft; content outside the section is untouched.
  - `seh install` merges the update check into `.codex/hooks.json` (`SessionStart`, matcher `startup|resume`). It runs only in a trusted project after the user reviews it in `/hooks`; setup says so. `scripts/check-update --host codex`.
  - `seh uninstall` removes only seh-owned entries from `.agents/skills`, which other tools also read.
  - `modelSuggest`: architect `gpt-6-sol`, implementer, reviewer and brainstorm `gpt-6.1-sol`, consultant `gpt-6-luna`. Availability per account is unverified; "no change" omits `model`. Reasoning effort is not configured.
  - `/<prefix>grillit` no longer takes the host from a `skillsDir` shared by several rows (`.agents/skills`): it uses the tool it runs in, or asks once. On Codex the brainstorm model is requested in the persona launch prompt (`Use model <id>.`); the Codex docs name no per-launch model parameter, so the runtime may not honour it.

### Fixed

- Codex: `$_setit-se` stopped with `BLOCKED: seh install has not been run here` although the install was complete. With the default prefix `_`, the model put the typed invocation into a shell path check, and the shell read `$_setit-se` as `$_` plus `setit-se`, so every `skillsDir` looked empty. The entry check now names the skill directory `<prefix>setit-se`, tells the model to test the literal quoted path and never to put the typed invocation in a shell command, and says a missing git repository is git disabled, never `BLOCKED`.

## [1.1.0] - 2026-11-13

Version reset from `2.0.0`: seh has no production users yet. First changelog entry.

### Added

- OpenCode slash commands. OpenCode does not turn skills into `/` commands, so `/_setit-se` did not exist there. The host table now has `commandsDir` (`.opencode/commands` for OpenCode, `null` elsewhere).
  - `seh install` writes `<commandsDir>/<prefix>setit-se.md` from `references/host-command.md`, a thin wrapper that loads the skill and passes `$ARGUMENTS`. A prefix change moves it. `seh uninstall` removes it.
  - `/<prefix>setit-se` writes the same wrapper for each work skill.
  - Each command names its host row (`Host: <id>`). `/<prefix>grillit` takes the host from that line before matching `skillsDir`, because OpenCode also loads `.claude/skills` and could otherwise pick Claude model ids. Persona and facilitator launches pass the brainstorm model explicitly.
- OpenCode work skills get `disable-model-invocation: true`, as on Cursor. The model no longer starts `/<prefix>shipit` and the others on its own. The host commands still load them by id. A copy without the field counts as missing, so a later `/<prefix>setit-se` repairs it.
- `/<prefix>setit-se` repairs incomplete host trees on a later run. If a live agent, work skill, or host command is missing while the version and prefix are unchanged (for example a new host row or `commandsDir`), it regenerates them and names the missing paths.
- Jira and Azure DevOps read-only mode (`agents.tracker.readOnly`). seh only reads the tracker; spec, prompt, log, and status live in repo files. Every write verb of `.seh/scripts/jira` and `.seh/scripts/ado` is `BLOCKED:`.

### Changed

- `/<prefix>setit-se` tracker flow: pick the tracker (files, Jira, Azure DevOps), then the read-only question, then the connection, token, and mapping. Read-only maps only `blocker` and `fetchFields`.

### Fixed

- OpenCode `modelSuggest` and the config skeleton mixed model generations (`anthropic/claude-opus-4-5`, `anthropic/claude-haiku-4-5`). They now use `anthropic/claude-opus-5-5` and `anthropic/claude-haiku-5-5`. Existing `harness.config.json` values are not changed.
- OpenCode skipped the `architect`, `implementer`, and `reviewer` agents ("agent file skipped"): a string `tools:` is invalid there. `/<prefix>setit-se` now removes `name` and `tools` from OpenCode agent copies (the name comes from the file) and keeps `mode: subagent`. A copy in the old shape counts as missing, so a later run repairs it without a version bump.
- OpenCode showed `Plugin failed: …/.opencode/plugins/seh-check-update.js` on every start. The plugin now uses the OpenCode V2 shape: a default export `{ id, setup }`, events from `ctx.event.subscribe` (`session.created`), and the notice added through `ctx.session.instructions.entry.put` (key `seh-update`). Top-level sessions only. The check runs for each new session (so a long-running OpenCode server sees a later release), uses the script's 24h cache, and never blocks OpenCode.
- `seh install` without `--prefix` reset an existing project to `_`. It now keeps the prefix in `.seh/PREFIX`, so updating no longer renames the skills. `_` is used only on a first install or when `.seh/PREFIX` holds a disallowed value.
- Autonomous `/<prefix>shipit` asked the user at the end. Architect now fixes a clear misspelling in a requested name (for example `substract` → `subtract`) in `critical` / `autonomous` and records it as `Q<n>`, and never leaves a choice open for the user. The autonomous final report lists decisions and asks nothing.

- `jira meta` and `ado meta` listed every custom field on the Jira site or in the ADO organization, so `/<prefix>setit-se` offered fields that the project does not use (for example ones left over from another project). Jira now takes fields from the project’s create metadata per issue type, with paging. ADO takes them from the project’s work item types. A field appears once even when several types have it.
- Skills and agents named Claude Code tools (`Agent tool`, `wrap_up`, `WebSearch`), which Cursor and OpenCode do not have. The text now says what to do (launch Consultant as a subagent, search the web, end-of-turn summary) without naming one host’s tool.

### Removed

- `agents.tracker.artifactsOnTrackerOnly`. A tracker in full write keeps spec, prompt, log, and status only on the issue or work item, never in repo files. The setit-se question for it is gone. A leftover key in an existing config is ignored.
