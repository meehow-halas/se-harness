## Stage spec

### Goal

Publish the four work skills with the shared guard.

### Scope in

- `planit`: launch Architect once; offer the next step (`doit` or `shipit`); do not start it. Brainstorm needed → stop and ask `/<prefix>grillit`.
- `doit`: launch Implementer (Consultant inside each phase) for existing spec + prompt. Same for bugs and features. Do not start Architect or Reviewer.
- `checkit`: one Reviewer round. Variants: review (default) and update (`update-from-base`). Report ❌ and offer `/<prefix>doit`; do not chain into Implementer.
- `shipit`: 1) no spec or prompt → Architect; 2) spec+prompt, no implementation → Implementer; 3) implementation exists → Reviewer; 4) open ❌ → Implementer with those items, then Reviewer again (max 3); 5) interactive stops on agent questions; critical/autonomous ends with PR URL on clean review; never merges. Starts at first missing stage; stops if already `done`; no pauses without question or stop; mode from intent, default `interactive`.
- Guard for all four before work: (1) `.seh/` or `.seh/VERSION` missing → `BLOCKED:` run `seh install` here then `/<prefix>setit-se`; (2) `harness.config.json` missing → `BLOCKED:` run `/<prefix>setit-se`; (3) `.seh/VERSION` ≠ `seh.generatedFrom` → `BLOCKED:` run `/<prefix>setit-se`.

### Scope out

- Setup (stage 05), brainstorm (stage 07), user-facing Consultant skill, PR merge, extra CLI.

### Acceptance criteria

- Four templates exist under `skills/`, generated by setup, not install.
- All four implement the guard.
- `planit` does not implement or review; `doit` does not spec; `checkit` is one round; `shipit` matches the pipeline and does not merge.
